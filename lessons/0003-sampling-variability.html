Урок 03 · Sampling variability

Почему p99 меняется
между запусками?

Система может остаться прежней или стать быстрее, а измеренный p99 — вырасти. Отделим sampling variability (выборочную изменчивость) от изменения распределения задержек.

Вспомни без конспекта: почему рост p99(success) может сопровождать улучшение сервиса? В прошлом уроке изменялся состав успешных запросов. Сегодня зафиксируем состав population (генеральной совокупности): все наблюдения относятся к одной заранее определённой группе, без ошибок, time limits и отбора по исходу.

Задача урока — уметь объяснить, почему разность двух sample quantiles (выборочных квантилей) ещё не доказывает изменение population quantile (квантиля распределения).

01

Распределение запросов и распределение оценок

Внутри одного запуска есть sample (выборка) из n времён запроса. По ней вычисляется одна оценка p99. При повторении запуска получаем другую выборку и другую оценку.

Latency distribution (распределение задержек) описывает времена отдельных запросов. Sampling distribution (выборочное распределение) описывает значения estimator (статистической оценки) при повторном получении выборок.

Вторая величина зависит от первой, от n и от способа оценивания quantile (квантиля). Даже при неизменном распределении задержек оценка не обязана повторяться.

В лаборатории используем Pareto distribution (распределение Парето) с известной квантильной функцией:

\[Q(p)=\frac{15}{(1-p)^{2/3}}\;\mathrm{ms}.\]Population p50 ≈ 23.81 ms, p95 ≈ 110.52 ms, p99 ≈ 323.17 ms.

Это учебный источник данных с длинным хвостом. Его параметры заданы для проверки оценок, а не подобраны к твоей БД. В production истинный Q(p) неизвестен.

Определение Pareto: SciPy, shape = 1.5, scale = 15, loc = 0. Вычисление inverse ECDF (обратной эмпирической функции распределения) не требует предположения о Pareto или normality (нормальности).

02

Повтори один эксперимент 200 раз

Каждая пара содержит два независимых запуска A и B по n запросов. При ускорении 0% распределения одинаковы. При ускорении 10% модель B масштабирует все времена на 0.9: её истинный p99 ровно на 10% ниже.

Запросы в симуляции i.i.d. — independent and identically distributed (независимы и одинаково распределены). Пары A/B здесь не являются paired queries (парными измерениями одних запросов).

Диапазон симулированных оценок не является confidence interval (доверительным интервалом), построенным по твоим production observations. Здесь распределение известно, а мы изучаем поведение estimator. Как получить интервал из реальных данных — отдельная задача.

  1. При n = 200 и 0% изменения посмотри, как часто sample p99 B выше A. Почему это возможно без регрессии системы?
  2. Выбери n = 50, затем 5000, каждый раз нажимая кнопку. Что происходит с диапазоном оценок p99? Что происходит с maximum (максимумом)?
  3. Установи истинное ускорение 10%. Остались ли пары, в которых измеренный p99 B оказался выше? Объясни, почему наличие таких пар не опровергает заданное ускорение.
Ожидаемые наблюдения

При одинаковых непрерывных распределениях и равных n независимые оценки p99 симметричны относительно перестановки A/B: вероятность положительной разности равна 1/2. В 200 парах доля будет колебаться около 50%. Это относится к знаку сырой разности, а не к частоте ошибок статистического теста.

При большем n оценка фиксированного p99 в этой модели обычно концентрируется ближе к истинному значению. Maximum при этом сдвигается к большим значениям. Даже при истинном ускорении оценки из конечных samples могут поменяться местами.

03

Почему разброс вообще возникает

Пусть T(1) ≤ ⋯ ≤ T(n) — order statistics (порядковые статистики), то есть отсортированные времена. При нашем правиле inverse ECDF:

\[\widehat q_p=T_{(k)},\qquad k=\lceil np\rceil.\]

Зафиксируем время t. Событие T(k) ≤ t означает, что как минимум k запросов уложились в t. Для каждого независимого запроса вероятность этого равна F(t). Поэтому число таких запросов имеет Binomial distribution (биномиальное распределение):

\[\begin{aligned}C_t&=\sum_{i=1}^{n}\mathbf1\{T_i\le t\}\sim\operatorname{Binomial}(n,F(t)),\\\mathbb P(\widehat q_p\le t)&=\mathbb P(C_t\ge k).\end{aligned}\]

Это точное распределение оценки, заданное через вероятность binomial event (биномиального события). Ни normal distribution (нормального распределения) задержек, ни asymptotic approximation (асимптотического приближения) для этого равенства не требуется. Независимость и одинаковое распределение наблюдений требуются.

Сколько наблюдений вообще попадает за истинный p99?

Для непрерывного распределения F(qp) = p. Ожидаемое число запросов за истинным qp равно n(1 − p): это сумма n индикаторов с математическим ожиданием 1 − p.

Это expectations (математические ожидания), а не гарантированные количества и не правило «10 достаточно». Подсчитываются значения за истинным quantile, а не за вычисленным sample quantile. Binomial-основа quantile inference: SciPy: quantile_test.

При n = 50 индекс p99 равен ⌈49.5⌉ = 50. Значит, наш sample p99 совпадает с maximum. Для других quantile estimators с interpolation это точное равенство может не выполняться.

Дополнение: почему важна local density (локальная плотность)

Даже одинаковое n не задаёт погрешность в ms. На пологом участке CDF небольшой сдвиг вероятности соответствует большому сдвигу времени. Формально, если f — probability density (плотность вероятности), непрерывная и положительная около qp, то F(qp + δ) ≈ p + f(qp)δ.

Для i.i.d. observations и фиксированного 0 < p < 1 асимптотическая standard error (стандартная ошибка) обычной quantile estimate имеет вид:

\[\operatorname{SE}(\widehat q_p)\approx\frac{\sqrt{p(1-p)}}{\sqrt{n}\,f(q_p)}.\]

Множитель \(\sqrt{\frac{p(1-p)}{n}}\) приходит из колебаний доли наблюдений; деление на f переводит сдвиг probability в сдвиг времени. Малая density увеличивает погрешность. При прочих равных четырёхкратное n асимптотически уменьшает SE вдвое. Это приближение, а не finite-sample guarantee (гарантия для конечной выборки).

Нормальный предел оценки не означает normality исходных данных. Сам theorem и его условия: Geyer, §7.4, Theorem 7.27, печатные стр. 205–206. Для дискретных данных или массы у time limit условия нужно проверять заново.

04

Почему maximum зависит от n

Пусть Mn = max(T1, …, Tn). Максимум не превышает t тогда и только тогда, когда все n наблюдений не превышают t. При независимости:

\[\mathbb P(M_n\le t)=F(t)^n.\]

Для любого t с 0 < F(t) < 1 эта вероятность уменьшается при росте n. Поэтому распределение максимума сдвигается к большим значениям даже у неизменной системы. Это не утверждение, что каждый следующий независимый запуск обязательно имеет больший maximum.

Для истинного p99 нашей непрерывной модели F(q0.99) = 0.99. При 50 запросах вероятность, что maximum не дойдёт до истинного p99, равна 0.9950 ≈ 60.5%. Поэтому «мы ни разу не увидели больше этого времени» не устанавливает upper bound (верхнюю границу) latency.

В обсуждении твоего ответа снижение max было возможным плюсом. Теперь добавляем условие интерпретации: сопоставимые n, workload и длительность наблюдения; даже после этого остаётся sampling uncertainty (неопределённость из-за конечной выборки).

05

Проверь причинное объяснение

1. При 0% изменения истинный p99 один и тот же, а измеренные p99 различаются. Что произошло?
2. При n = 50 чему равен sample p99 по inverse ECDF?
3. После уменьшения размера выборки maximum снизился. Какое объяснение допустимо без дополнительных данных?
4. Что означает диапазон [p5; p95] в таблице симулятора?

Ответы без JavaScript

1: изменилась случайная выборка. 2: T₍₅₀₎. 3: возможно влияние n. 4: интервал распределения оценок.

Проверь на своём benchmark

Коллега сравнил два запуска: p99 вырос с 300 до 330 ms, maximum снизился с 2000 до 1500 ms. По этим четырём числам ещё нельзя выбрать объяснение.

В 3–5 предложениях запиши, какие сведения о n, workload, status/limit-hit rates и повторных запусках нужны для интерпретации. Отдельно объясни разницу между механизмом урока 02 и механизмом этого урока.

Черновик хранится только локально, если это разрешено браузером.

Для твоей БД i.i.d. — проверяемое условие, а не данность: общие GC pauses, workload drift и запросы внутри одного run могут создавать dependence (зависимость). Простое увеличение счётчика запросов не доказывает пропорциональный прирост независимой информации. Выбор единицы повторения и корректный resampling (повторная выборка) будут отдельными уроками.

Критерий завершения

Ты различаешь разброс latency и разброс её оценки, можешь объяснить k = ⌈np⌉ и зависимость maximum от n. По одной разности sample p99 не объявляешь изменение системы доказанным.

Создание урока и локальная отметка не означают подтверждение знаний.

Retrieval practice (практика воспроизведения) через 1–3 дня: без конспекта выведи P(Mn≤t)=F(t)^n и объясни, почему n=50 делает inverse-ECDF p99 максимумом. Автоматические напоминания не настроены.
